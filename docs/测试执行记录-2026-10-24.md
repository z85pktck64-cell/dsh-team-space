## 4. 发现的缺陷

### 4.1 【P0 · 已修复】store 损坏会静默清空团队数据

- 现象：`team-space.json` 出现非法 JSON 时，`loadStore()` 的 `catch` 直接返回空 store；下一次任意写操作会用空数据覆盖原文件。
- 证据：修复前 `node dev/check-store.mjs` 3 条失败，写入接口返回 200 且文件被覆盖为空表。
- 修复：`lib/index.js` 改为「读失败但文件存在 → 抛错停写，原文件不动」；仅 `ENOENT` 才当首次运行。
- 复验：`check-store.mjs` 5/5 通过。

### 4.2 【P1 · 已修复】企微通知不看响应码

- 现象：`await fetch(...)` 没有检查 `response.ok`，企微返回 500 仍被当作发送成功，日志里也没有失败记录。
- 修复：非 2xx 记 `failed` + `console.error`；新增 `TEAM_SPACE_NOTIFY_URL`（覆盖目标）与 `TEAM_SPACE_NOTIFY_LOG`（JSONL 记录，含 skipped 原因）。
- 复验：mock 场景断言 `webhook 返回 500 → failed，委托仍创建成功` 通过。

### 4.3 【P1 · 已记录】三端 `list_members` 返回结构不一致

| 端 | 返回 |
|---|---|
| `GET /member/list` | `{ members: [{ name, bio }] }` |
| agent 工具 | `{ count, members: ["名字：简介"] }` |
| MCP | `{ onlineDevices, totalDevices, devices, memberCards }` |

成员**集合**一致，但结构三套。已在方案 G04 改为「集合一致、结构各自约定」；若产品要求统一，需要单独排期。

### 4.4 【P1 · 已修正用例】D07 过期

原用例要求「安装团队空间自己 → 403」，但代码已改成只拦 link 安装。方案 D07 期望已更新。

### 4.5 【P1 · 已修复】发布门禁形同虚设

- 现象：`release.sh` 里写的是 `node dev/xxx.mjs | tail -2`。管道的退出码取 `tail`，永远是 0，测试失败发布会继续。
- 修复：改成 `run_check` 函数，失败时打印最后 30 行并 `exit 1`；同时接入 `e2e-p0` 与 `check-store`。
- 验证：用必然失败的命令跑 `run_check`，确认中止（exit=1）。

### 4.6 【P1 · 已修复】门店端升级后依赖与 lockfile 仍指向旧包

- 现象：Neo 的目录已是 2.7.86，但 profile 依赖仍指 2.7.64、lock 指 2.7.58，下一次重装会静默回退。
- 根因：同名依赖更新被提前 return 跳过；请求名 `dsh-team-space` 与真实包名 `@local/dsh-team-space` 不一致，依赖写错 key。
- 修复：按已安装 `package.json` 的真实包名更新；固化本次安装目录为 tgz；同步 profile 依赖和 pnpm lock。
- 复验：Neo 依赖 / lock / 包均为 2.7.86；pnpm `--frozen-lockfile` 与 DSH 重启后均不回退。

### 4.7 【P1 · 已修复】新增记录按钮错误显示「保存更新」

- 现象：新增链接时编辑对象是空对象 `{}`，按钮用 `editing ? '保存更新' : '保存'` 判断，空对象也是 truthy，于是新增也显示「保存更新」。
- 修复：`lib/client.js` 改为 `editing?.id ? '保存更新' : '保存'`。
- 复验：H05 真实点击新增链接，弹窗按钮为「保存」，保存后立即出现在列表中。

### 4.8 【P1 · 已修复】版本冲突时「接管这条记录」被弹窗遮罩挡住

- 现象：保存触发 `VERSION_CONFLICT` 后，冲突条已经渲染，但编辑弹窗和遮罩仍保留在上层，「接管这条记录」无法点击。
- 修复：冲突分支 `setEditing(null)` 关闭弹窗；草稿已保存在 `conflict.draft`，接管时继续使用，不丢输入。
- 复验：H14 另起一次写入制造冲突，冲突原因、接管按钮、接管后的作者回切均正常。

### 4.9 【P2 · 已修复】断网时把浏览器原文 `Failed to fetch` 显示给用户

- 现象：认领 / 分享请求被中断时，界面直接显示 `Failed to fetch`，门店同事不知道是网络问题还是操作失败。
- 修复：客户端统一包装网络异常——本机请求提示「连不上本机 DSH 服务，请确认 DSH 仍在运行后重试」，团队空间请求提示「连不上团队空间服务器，请检查网络或服务器地址后重试」。
- 复验：J08 认领 / 分享各 4 项，共 8/8 通过；提示为中文，页面不白屏，服务端状态不变。
