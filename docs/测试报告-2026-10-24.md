## 3. 方法

1. **能力 × 入口**：同一能力的所有入口都跑，并比对结果与副作用（不是只测一条 HTTP 路由）。
2. **副作用单验**：通知、落盘、profile 写入、备份、通道标记分别断言。
3. **数据纪律**：所有写操作走 `x-team-space-channel: test`，每条用例自带清理，结束断言零残留。
4. **分层**：L1 静态契约 → L2 接口 → L3 多路径 → L5 通道 → L7 安装；UI 与跨机器单独标注。

## 6. 缺陷清单

### 6.1【P0 · 已修复】store 损坏会静默清空团队数据

- 现象：`team-space.json` 非法 JSON → `loadStore()` 返回空 store → 下一次写用空数据覆盖原文件。
- 证据：修复前 `check-store` 3 条失败，写接口返回 200 且文件被覆盖为空表。
- 修复：文件存在但解析失败 → 抛错停写，原文件不动；仅 `ENOENT` 返回空 store。

### 6.2【P1 · 已修复】企微通知不看响应码

- 现象：`fetch` 未检查 `response.ok`，500 被当成发送成功，日志无记录。
- 修复：非 2xx 记 `failed` + 错误日志；新增 `TEAM_SPACE_NOTIFY_URL` / `TEAM_SPACE_NOTIFY_LOG`。

### 6.3【P1 · 已修复】发布门禁形同虚设

- 现象：`release.sh` 用 `node xxx | tail -2`，退出码取 `tail`（恒 0），测试失败仍继续发布。
- 修复：`run_check` 失败打印日志并 `exit 1`；同时接入 `check-store`、`e2e-p0`。

### 6.4【P1 · 已记录】三端 `list_members` 结构不一致

| 端 | 返回 |
|---|---|
| `GET /member/list` | `{ members: [{ name, bio }] }` |
| agent 工具 | `{ count, members: ["名字：简介"] }` |
| MCP | `{ onlineDevices, totalDevices, devices, memberCards }` |

成员集合一致，结构三套。方案 G04 已改为「集合一致、结构各自约定」；要统一需单独排期。

### 6.5【P1 · 已修复】门店端升级后依赖与 lockfile 仍指向旧包

- 现象：Neo 目录已是 **2.7.86**，但 profile 仍为 `@local/dsh-team-space: file:...2.7.64.tgz`，`pnpm-lock.yaml` 指向 2.7.58；下一次 profile 重装会静默回退。
- 根因 1：`registerProfileDependency` 发现同名依赖就直接跳过，版本永远不更新。
- 根因 2：安装请求名是 `dsh-team-space`，真实包名是 `@local/dsh-team-space`；依赖写错 key 会留下旧 `@local` 依赖。
- 修复：enable 以已安装 `package.json` 的真实包名为准；把当前目录固化为 `~/.dsh/plugins/<短名>-<版本>.tgz`；同步更新 profile 依赖与 `pnpm-lock.yaml` 的 importer / packages / snapshots。
- Neo 复验：依赖、lock、固化包均为 2.7.86；Neo 自带 pnpm `--offline --frozen-lockfile` 重装仍为 2.7.86；DSH 重启后依赖与 lock 未被改回。
- 回归：`mock-host` 增加 5 项 J09 断言（含真实 pnpm 重装），selftest 增加 2 项源码护栏。

### 6.6【P2 · 已修正用例】D07 过期

原用例要求「安装自己 → 403」，代码已改为仅拦 link 安装；方案 D07 期望已更新。

### 6.7【P1 · 已修复】新增记录按钮错误显示「保存更新」

- 现象：新增链接时 `editing` 是空对象 `{}`，truthy 判断导致按钮显示「保存更新」。
- 修复：`lib/client.js` 改为按 `editing?.id` 判断。
- 复验：H05 新增链接弹窗按钮为「保存」，保存后记录立即出现。

### 6.8【P1 · 已修复】版本冲突时「接管这条记录」无法点击

- 现象：冲突条已经出现，但编辑弹窗与遮罩仍在最上层，接管按钮被挡住。
- 修复：冲突时关闭编辑弹窗；草稿保存在 `conflict.draft`，接管时继续使用。
- 复验：H14 冲突提示、接管按钮、接管后作者回切全部通过。

### 6.9【P2 · 已修复】断网时界面显示原始 `Failed to fetch`

- 现象：认领 / 分享请求失败时直接暴露浏览器错误，缺少可行动信息。
- 修复：客户端区分本机与团队空间服务器，统一提示「连不上…请…重试」。
- 复验：J08 认领 / 分享共 8 项检查全部通过，服务端状态未被误写。
